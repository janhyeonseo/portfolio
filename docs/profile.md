#### 1. 레거시 C# 프로그램 → React 이관 (화면 10종 + 팝업 11종 = 21종)
- 레거시 C# 화면의 구조·업무 규칙을 분석해 React + Spring으로 재구현
- 로직 파악이 어려운 부분은 상급 개발자와 페어링으로 분석·검증

#### 2. 3-그리드 계층 연동 화면 (표준 프로세스 구성 화면 3종) ★핵심
- 구조: 프로세스 → Task → 하위 프로세스, 3개 그리드가 서로 연결된 화면
- UI: 그리드 간 선택 이동(양방향), 행 순서 변경, 변경 감지 후 저장 전 확인(confirm)
- 문제: 현업 요구 UI 특성상 행별 CRUD 상태 플래그(I/U/D)를 프론트에서 보낼 수 없는 구조
- 해결: 프론트는 그리드 전체 데이터만 전송 → 서버에서 기존 DB 데이터와 Map-List diff 비교로 INSERT/UPDATE/DELETE 자동 도출
- 성능: 레거시에서 7~9초 걸리던 화면 로딩을 593ms로 개선 (약 93% 단축, 브라우저 개발자도구 Network 탭 측정)
  - 원인/조치: 쿼리 재작성 + 불필요한 API 호출 제거 (둘 다)
- 결과: 현업이 사용을 꺼리던 화면이 실사용 가능해짐
- E2E 표준 프로세스 영역 화면 총 6종 중 3종이 3-그리드 구조

#### 3. 4뎁스 메가메뉴 (프론트+백엔드 전담)
- 문제: 사내 공통 메뉴 컴포넌트는 3뎁스까지만 지원
- 서버: 부모-자식 계층 쿼리(Oracle CONNECT BY / SYS_CONNECT_BY_PATH)로 메뉴 경로를 '/'로 이어 조회
- 프론트: 경로 문자열을 split('/') → 정렬 → 트리로 가공하는 함수를 직접 작성, 4뎁스 서브메뉴 우측 전개
- 디테일: 긴 메뉴명 2줄 처리, 권한별 클릭 제어
- 화면 마크업은 직접 구조를 잡고 퍼블리셔가 스타일 적용 (협업)

#### 4. HOME 화면 신규 개발
- 상단: 포털 소개 영역
- 바로가기 카드 4개: 메뉴 쿼리를 재사용해 부모-자식/권한별로 분류, 권한 없는 메뉴는 딤 처리
  - 카드당 메뉴 5개, 초과 시 하단 점(●○) 클릭으로 페이지 전환
  - 메뉴명 높이 실측(offsetHeight / lineHeight) 기반 동적 페이지 분할
- 결재 현황: 기존 화면의 API·쿼리를 재사용(조건만 추가)해 신규 API 없이 요약 표시, 바로가기 제공
- 공지사항: 최신 4건 표시, 클릭 시 공지사항 페이지 이동 (공지사항 페이지도 직접 개발)
- HELP 데스크 등 기타 링크
- 디자이너 시안 기반 구현 + 상호 피드백

#### 5. 계획구성도 상세 화면 (약 3,700줄, UI 전담)
- 장비 유형별 동적 그리드/팝업 파라미터 분기, 탭·트리·팝업 복합 화면
- 행 추가·삭제·복사 시 자동 채번 ("미사용 값 기준 채번"으로 중간 행 삭제 시 번호 어긋남 해결)
- Chamber 최대 개수 검증 등 상태별 유효성 검사
- 임시저장 → 구매검토요청 → 승인/반려 결재 흐름 구현
- 리비전 비교 팝업: 트리 구조 비교, Expand/Collapse, 버전 간 diff 표시

#### 6. 공지사항 · 즐겨찾기 · 공통 화면
- 공지사항: 목록·상세·등록·댓글·N-Depth 대댓글·첨부파일·조회수 (계층 쿼리 + 트리 변환)
- 즐겨찾기: 폴더-메뉴 트리, 폴더 CRUD, 사이드바 연동
- 공통 화면 약 20개 한/영/중 3개 국어 지원, 공통 라우팅 팝업에 파라미터 기능 추가(팀 공통 프레임워크 기여)
